`@genicui/vite-plugin` adds zero-config auto-registration for GenicUI components in any Vite-powered project. Drop the plugin into `vite.config.ts`, place `GenicElement` subclasses under your chosen components directory, and the plugin discovers them, registers the custom elements, and emits a `genui-registry.json` on every build.

For the rationale behind the plugin shape, see [Concepts → Components](/concepts/components#auto-registration).

## `viteGenicUI(options?)`

```ts [packages/vite-plugin/src/index.ts]
export { viteGenicUI } from './plugin.js';
```

Factory for the Vite plugin. Returns a `Plugin` object suitable for `defineConfig({ plugins: [...] })`.

| Parameter | Type | Required | Description |
| --- | --- | --- | --- |
| `options.componentsDir` | `string` | no | Directory containing `GenicElement` subclass `.ts` files. Default: `'src/genui/components'`. |
| `options.registryOutput` | `string` | no | Output path for the generated registry JSON, relative to `vite.config.ts`. Default: `'genui-registry.json'`. |

**Returns:** `Plugin` — a Vite plugin instance.

### What the plugin does

1. **Auto-discovery** — on `load('genicui:components')`, scans `componentsDir` recursively for `.ts` files, parses each with the AST scanner, and collects every `class X extends GenicElement` declaration.
2. **Virtual module** — generates a virtual module that imports each component file. Components self-register via `customElements.define()` calls inside their source files.
3. **HMR** — on `handleHotUpdate`, re-scans the components directory, invalidates the virtual module, and sends a `full-reload` HMR event scoped to `componentsDir/**`.
4. **Registry emission** — on `closeBundle()`, writes `genui-registry.json` at the project root with the discovered `[{ name, tag, file, version, propsSchema?, events? }]` entries.

### Example — `vite.config.ts`

```ts [vite.config.ts]
import { defineConfig } from 'vite';
import vue from '@vitejs/plugin-vue';
import { viteGenicUI } from '@genicui/vite-plugin';

export default defineConfig({
  plugins: [
    vue(),
    viteGenicUI({
      componentsDir: 'src/genui/components',
      registryOutput: 'genui-registry.json',
    }),
  ],
});
```

### Default conventions

- File extension: `.ts` only (`.tsx` is not auto-scanned).
- Class naming: any `class X extends GenicElement` is picked up; tag defaults to `genui-<kebab-class-name>`.
- Tag override: if a class also calls `customElements.define('my-tag', X)`, that tag wins.
- Static metadata: `static propsSchema = { ... }` and `static events = { ... }` are extracted and copied into `genui-registry.json`.

## `scanComponentFile(code)`

```ts [packages/vite-plugin/src/index.ts]
export { scanComponentFile } from './scanner.js';
```

Pure AST scanner for `GenicElement` subclasses. Used internally by the plugin and exported for tooling (lint rules, custom CLI commands, test fixtures).

| Parameter | Type | Description |
| --- | --- | --- |
| `code` | `string` | TypeScript source code to scan. |

**Returns:** `ComponentMeta[]` — one entry per discovered component. Empty array if parsing fails or no subclasses are found.

```ts [ComponentMeta shape — from packages/vite-plugin/src/types.ts]
interface ComponentMeta {
  className: string;
  tag: string;
  file: string;
  propsSchema?: Record<string, unknown>;
  events?: Record<string, unknown>;
}
```

**Example — using the scanner standalone**

```ts
import { scanComponentFile } from '@genicui/vite-plugin';
import fs from 'node:fs';

const source = fs.readFileSync('src/genui/components/data-table.ts', 'utf-8');
const metas = scanComponentFile(source);
// → [{ className: 'DataTable', tag: 'genui-data-table', file: '...', propsSchema: {...}, events: {...} }]
```

### What the scanner detects

| Construct | Effect on output |
| --- | --- |
| `class X extends GenicElement` | Adds `X` to the discovered-classes set with default tag `genui-<kebab>`. |
| `class X extends ns.GenicElement` | Same as above — `member-expression` extends is also accepted. |
| `customElements.define('my-tag', X)` | Overrides the default tag for class `X`. |
| `static propsSchema = { ... }` | Captured into `meta.propsSchema` (literal objects only — identifiers / function calls evaluate to `undefined`). |
| `static events = { ... }` | Captured into `meta.events` (same literal-only caveat). |

::tip
Only **literal object expressions** are captured into `propsSchema` and `events`. If you need to share a schema across files, lift it into a `.ts` constant and re-import — or duplicate the literal in each component file. Identifier references evaluate to `undefined` in the AST walk.
::

## Registry output

After a successful build, the plugin writes:

```json [genui-registry.json]
{
  "version": "1.0.0",
  "components": [
    {
      "name": "DataTable",
      "tag": "genui-data-table",
      "file": "src/genui/components/data-table.ts",
      "version": "1.0.0",
      "propsSchema": { "type": "object", "additionalProperties": false, "required": ["rows"], "properties": { "rows": { "type": "array" } } },
      "events": { "row_selected": { "type": "object" } }
    }
  ]
}
```

The schema is consumed by the server-side registry loader (F37) and the runtime component catalog. If you change a component's `propsSchema`, regenerate by re-running the build.

## Types

```ts [packages/vite-plugin/src/index.ts]
export type {
  ComponentMeta,
  GenicUIPluginOptions,
  GenicUIRegistry,
  RegistryEntry,
} from './types.js';
```

| Type | Description |
| --- | --- |
| `ComponentMeta` | Per-file discovery result (above). |
| `GenicUIPluginOptions` | `{ componentsDir?: string; registryOutput?: string }`. |
| `GenicUIRegistry` | `{ version: string; components: readonly RegistryEntry[] }`. |
| `RegistryEntry` | `{ name, tag, file, version, propsSchema?, events? }` — one row of `genui-registry.json`. |

## Caveats

- The scanner uses `@babel/parser` and may reject exotic syntax (decorators, `declare class`). Stick to plain TypeScript.
- The virtual module ID is the literal string `'genicui:components'`. Import it from your entry file with `import 'genicui:components'` to trigger registration, or call `customElements.define()` yourself for explicit control.
- The plugin emits the registry at `closeBundle()` — `vite dev` does **not** write the file. Run `vite build` to refresh it.
