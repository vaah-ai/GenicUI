`@genicul-primevue/registry` is the canonical PrimeVue-backed component registry. Each component ships with a JSON Schema describing its props (with `additionalProperties: false` enforced) and the event payloads it emits. The server-side catalog mirrors these schemas; the client-side PrimeVue components render the validated props.

For the trust-boundary rationale behind `additionalProperties: false`, see [Concepts → Trust Boundary](/concepts/trust-boundary). For how registries are loaded, see [Concepts → Components](/concepts/components#registry-loader).

The registry currently ships **5 components**. Each entry below is a verbatim copy of its `propsSchema` from [`registries/primevue/registry.json`](https://github.com/vaah-ai/GenicUI/blob/develop/registries/primevue/registry.json).

## data-table

Display tabular data with sorting, pagination, filtering, and selection. The most-used component in the catalog.

### Props (`additionalProperties: false`)

| Name | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `rows` | `Array<{ id: string; [k: string]: unknown }>` | **yes** | — | Row objects; each must have a string `id`. Additional per-row properties are allowed. |
| `columns` | `Array<{ key: string; label: string; sortable?: boolean; filterable?: boolean }>` | **yes** | — | Column descriptors — `key` is the property to read on each row, `label` is the header text. |
| `pageSize` | `integer` (1–100) | no | `10` | Rows per page. |
| `page` | `integer` (≥0) | no | `0` | Current zero-indexed page. |
| `sort` | `{ key: string; direction: 'asc' \| 'desc' }` | no | — | Active sort. If present, the table sorts by `key` in `direction`. |
| `filters` | `Record<string, string>` | no | — | Active filters keyed by column `key`. |
| `selection` | `{ mode: 'single' \| 'multiple'; dataKey?: string }` | no | — | Selection configuration. `dataKey` is the row property used to identify a row (defaults to `'id'`). |
| `loading` | `boolean` | no | — | Shows a loading overlay when `true`. |

### Events

| Event | Payload | Description |
| --- | --- | --- |
| `sort-change` | `{ key: string; direction: 'asc' \| 'desc' }` | User clicked a sortable header. |
| `filter-change` | `{ key: string; value: string }` | User edited a filter input on column `key`. |
| `selection-change` | `{ rowIds?: string[]; rowId?: string }` | Selection changed. `rowIds` is set for `mode: 'multiple'`; `rowId` is set for `mode: 'single'`. |
| `page-change` | `{ page: number; pageSize: number }` | User changed page or page size. |
| `row-click` | `{ rowId: string }` | User clicked a row body. |

### Example — render request

```json [render_component arguments]
{
  "name": "data-table",
  "props": {
    "rows": [
      { "id": "1", "name": "Alice", "status": "active" },
      { "id": "2", "name": "Bob",   "status": "inactive" }
    ],
    "columns": [
      { "key": "name",   "label": "Name",   "sortable": true },
      { "key": "status", "label": "Status", "sortable": true, "filterable": true }
    ],
    "pageSize": 10,
    "page": 0
  }
}
```

### Loading + mounting example (full agent turn)

```ts [Concept snippet — see Concepts → MCP Tools for the full flow]
import { AgentBridge } from '@genicui/agent-bridge';

const bridge = await AgentBridge.connect(
  { provider: 'openai', apiKey: 'sk-...', model: 'gpt-4o' },
  'http://localhost:3040/mcp',
);

const reply = await bridge.execute('Show me a data table of users and their status');
// → bridge finds data-table, renders it, and the agent's text reply
//   accompanies the rendered component in the chat panel.
```

## input-pair

Two-number input form with a Submit button. Emits a `submit` event with `{ input1, input2 }` when clicked; the agent bridge forwards the click into a follow-up turn so the agent can compute and return a `result-card`.

### Props (`additionalProperties: false`)

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `input1` | `number` | no | First number (pre-fill). |
| `input2` | `number` | no | Second number (pre-fill). |
| `label1` | `string` | no | Label for the first input. |
| `label2` | `string` | no | Label for the second input. |
| `submitLabel` | `string` | no | Submit button text (e.g., "Add them"). |
| `resultComponentId` | `string` | no | If set, the bridge targets the named `result-card` component for the answer. |

### Events

| Event | Payload | Description |
| --- | --- | --- |
| `submit` | `{ input1: number; input2: number }` | User clicked Submit. |

### Example

```json
{
  "name": "input-pair",
  "props": {
    "input1": 5,
    "input2": 3,
    "label1": "First number",
    "label2": "Second number",
    "submitLabel": "Add them"
  }
}
```

## result-card

Display-only card that surfaces a computed numeric answer. The natural follow-up to an `input-pair` submission.

### Props (`additionalProperties: false`)

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `input1` | `number` | no | Echoes the first input that produced the result. |
| `input2` | `number` | no | Echoes the second input. |
| `sum` | `number` | **yes** | The computed value (or operation result). |
| `operation` | `'add' \| 'subtract' \| 'multiply' \| 'divide'` | no | The operation performed. |
| `title` | `string` | no | Card title (e.g., "Sum"). |

### Events

None — `result-card` is display-only.

### Example

```json
{
  "name": "result-card",
  "props": {
    "input1": 5,
    "input2": 3,
    "sum": 8,
    "operation": "add",
    "title": "Sum"
  }
}
```

## city-picker

Interactive dropdown of cities with a Submit button. The first step in any weather flow — the user picks the city, the agent renders the `weather-card` for it.

### Props (`additionalProperties: false`)

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `initialCity` | `string` | no | Pre-selected city (must appear in `cityOptions`). |
| `cityOptions` | `string[]` (≥2 items) | **yes** | The list of cities the user can pick from. |
| `label` | `string` | no | Prompt text shown above the dropdown. |

### Events

| Event | Payload | Description |
| --- | --- | --- |
| `submit` | `{ city: string }` | User picked a city and clicked Submit. |

### Example

```json
{
  "name": "city-picker",
  "props": {
    "cityOptions": ["Paris", "London", "Tokyo", "New York", "Sydney"],
    "label": "Pick a city"
  }
}
```

::caution
**Always use `city-picker` first** for any weather query. The agent system prompt instructs the model: *"Do NOT guess a city and render a `weather-card` directly — let the user pick."* See [Concepts → Components](/concepts/components#when-to-use-city-picker) for the rationale.
::

## weather-card

Display-only weather card. Rendered only *after* a `city-picker.submit` event has fired (or the user has already named a specific city in the original prompt).

### Props (`additionalProperties: false`)

| Name | Type | Required | Description |
| --- | --- | --- | --- |
| `city` | `string` | **yes** | The city to display weather for. |
| `units` | `'metric' \| 'imperial'` | no | Display units. Defaults to metric. |

### Events

None — `weather-card` is display-only.

### Example

```json
{
  "name": "weather-card",
  "props": { "city": "Paris", "units": "metric" }
}
```

## PassThrough configuration

The PrimeVue-backed components use Vue's *PassThrough* (PT) pattern for fine-grained styling. Each component accepts a `pt` prop in addition to the schema above — for the full PrimeVue PassThrough API, see the [PrimeVue documentation](https://primevue.org/theming/#passthrough).

```ts [Customising a data-table's PassThrough]
import DataTableComponent from '@genicul-primevue/registry/components/data-table.vue';

const table = DataTableComponent as unknown as { __pt?: unknown };
// PassThrough is configured at mount time via the PrimeVue <PrimeVue> provider;
// the registry components inherit those defaults unless overridden.
```

::note
PassThrough customization is framework-level (PrimeVue), not a GenicUI surface. GenicUI does not pass an explicit `pt` object — applications customize it at the PrimeVue provider level.
::

## Trust boundary

Every prop schema above is `additionalProperties: false`. The server-side catalog rejects any prop that is not enumerated; the client-side component never receives unexpected keys. This is the trust boundary in action — see [Concepts → Trust Boundary](/concepts/trust-boundary).

If you add a prop to a component, you must:

1. Add it to `propsSchema.properties` in `registries/primevue/registry.json`.
2. Update the Vue component to read it.
3. Update the matching TypeBox schema in `packages/server/src/mcp/catalog.ts` (server-side validator).
4. Bump the component `version` field in `registry.json`.
