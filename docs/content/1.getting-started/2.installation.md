Install GenicUI's three runtime packages in any project that speaks WebSocket. The full reference walkthrough below targets **Nuxt 4** — the most-tested integration — but the server is framework-agnostic and runs anywhere Bun or Node runs.

## Prerequisites

::tabs
:::tab{label="Bun (preferred)"}
Bun 1.3.12 or later. GenicUI's server uses Bun's native WebSocket and HTTP server. [Install Bun](https://bun.sh/docs/installation).
```bash
bun --version
# >= 1.3.12
```
:::
:::tab{label="Node.js"}
Node.js 20 LTS or later. The server runs on Node via Elysia's Node adapter with equivalent behavior.
```bash
node --version
# >= v20.0.0
```
:::
::

You also need:

- A package manager — `bun`, `npm`, `pnpm`, or `yarn`.
- A working Nuxt 4 project (or any Vite-based app) for the client side.

## Scaffold a new project

::steps
### Create a fresh Nuxt 4 app

```bash
bun create nuxt@latest my-genicui-app
cd my-genicui-app
```

When the CLI prompts you to pick modules, skip `@nuxt/ui` for now — GenicUI ships its own components and you do not need a UI framework to render them.

### Install the GenicUI runtime

```bash
bun add @genicui/core @genicui/server @genicui/client
```

- **`@genicui/core`** — shared types, JSON-Patch engine, session store. Zero runtime dependencies.
- **`@genicui/server`** — Elysia HTTP + WebSocket server, MCP transport, four MCP tools.
- **`@genicui/client`** — `<genic-element>` Web Component, WebSocket client, React/Vue adapters.

### (Optional) Install the build + LLM adapters

```bash
bun add -D @genicui/vite-plugin
bun add @genicui/agent-bridge
```

- **`@genicui/vite-plugin`** — AST scans your Vue/React/Svelte sources for component schemas and emits `genui-registry.json` at build time.
- **`@genicui/agent-bridge`** — fetch-based LLM + MCP client you can drop into a Node backend to drive a GenicUI server from any model.

### (Optional) Install a component registry

```bash
bun add @genicul-primevue/registry
```

The PrimeVue registry ships twelve production components — `DataTable`, `Calculator`, `WeatherCard`, `CityPicker`, and more — each declared once in `registry.json` and rendered as Web Components in any framework.
::

## Configure your project

### 1. Start the GenicUI server

Create `server/genicui.ts` at the repo root:

```ts [server/genicui.ts]
import { createServer } from '@genicui/server';

createServer();
```

Then add a script to `package.json`:

```json [package.json]
{
  "scripts": {
    "genicui": "bun run server/genicui.ts"
  }
}
```

The server listens on `http://localhost:3040` by default. Override with `GENICUI_PORT` and `GENICUI_HOSTNAME` environment variables.

::callout{type="info"}
`createServer()` reads `GENICUI_API_KEY` and `GENICUI_REGISTRIES_DIR` from the environment. In dev mode, leaving `GENICUI_API_KEY` unset disables auth — every request is accepted. See [Trust Boundary](/concepts/trust-boundary) for production setup.
::

### 2. Mount the client in your app

For Nuxt 4, create a plugin:

```ts [app/plugins/genicui.client.ts]
import { defineNuxtPlugin } from '#app';
import { connectGenicUiClient } from '@genicui/client';

export default defineNuxtPlugin((nuxtApp) => {
  const client = connectGenicUiClient({
    url: 'ws://localhost:3040/ws',
  });
  nuxtApp.vueApp.provide('genicui', client);
});
```

For React, SvelteKit, or vanilla HTML, see the framework-specific recipes in [Guides → Development](/guides/development).

### 3. Render your first component

Add `<genic-element>` to any template:

```vue [app/pages/index.vue]
<template>
  <genic-element component-id="my-table" />
</template>
```

The server assigns the component ID when you call `render_component`. To trigger a render from your own code, POST to the MCP endpoint:

```bash
curl -X POST http://localhost:3040/mcp \
  -H "Content-Type: application/json" \
  -d '{
    "jsonrpc": "2.0",
    "id": 1,
    "method": "tools/call",
    "params": {
      "name": "render_component",
      "arguments": {
        "name": "DataTable",
        "props": { "rows": [] }
      }
    }
  }'
```

The response includes the assigned `componentId`. Pass that to `<genic-element>` and the table renders.

## Verify the install

::steps
### Start the server

```bash
bun run genicui
# → Server running at http://0.0.0.0:3040
```

### Hit the health endpoint

```bash
curl http://localhost:3040/health
# → {"status":"ok"}
```

### Open the playground

```bash
git clone https://github.com/vaah-ai/GenicUI.git
cd GenicUI/examples/playground
bun install
bun run dev
# → http://localhost:3000
```

The playground bundles a chat surface wired to the GenicUI server. Type "render a data table" and the agent renders one inline.
::

## Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| `EADDRINUSE :::3040` | Another process holds port 3040 | Set `GENICUI_PORT=4040` and update the client's `ws://...` URL |
| `WebSocket connection failed` | Server is on a different port/host | Check `GENICUI_PORT` and the client's `url` field |
| `Component "X" not found in catalog` | Registry directory not loaded | Set `GENICUI_REGISTRIES_DIR=./registries` and verify the directory exists |
| `<genic-element>` renders nothing | Component never mounted on the server | Confirm `render_component` was called and the `componentId` matches |

::callout{type="warning"}
**Do not import from `poc/`.** Per the project's contribution rules, the `poc/` directory contains proof-of-concept code only and is never promoted into the production packages. Always import from `@genicui/*` or `@genicul-primevue/registry`.
::
