This walkthrough boots the GenicUI Playground end-to-end on your machine, clicks a prompt, and watches a real `data-table` PrimeVue component appear inside the chat panel — then captures a row click back as a chat event. Total elapsed time: **under five minutes** on a fresh checkout with Bun installed.

The playground is the canonical worked example for GenicUI. It is a Nuxt 4 app wired to a real GenicUI server over WebSocket. Every step below maps to a control you can see in the running UI.

::callout{type="info"}
**Prerequisites:** Bun 1.3.12+, `git`, and an LLM CLI on `$PATH` (defaults assume Claude Code at `/opt/homebrew/bin/claude`). The example uses the bundled PrimeVue registry, so you do not need any other UI framework.
::

## The five-minute flow

::steps
### Clone and install

```bash
git clone https://github.com/vaah-ai/GenicUI.git
cd GenicUI
bun install
```

`bun install` links all four workspace groups (`packages/*`, `apps/*`, `examples/*`, `registries/*`) plus the playground's own Nuxt/PrimeVue dependencies.

### Start the GenicUI server

The server is the **transport layer** the playground talks to. It listens on HTTP `3040` and WebSocket `3041` by default.

```bash
GENICUI_REGISTRIES_DIR=./registries bun --filter @genicui/server start
```

You should see one line on stderr:

```text
Server running at http://0.0.0.0:3040
```

::callout{type="warning"}
`GENICUI_REGISTRIES_DIR` is required for the bundled PrimeVue registry to load. Without it, `find_ui_component` will return an empty catalog. See [Registries](/concepts/registries) for the discovery contract.
::

Verify the server is healthy and the catalog is populated:

```bash
curl http://localhost:3040/health
# → {"status":"ok"}

curl http://localhost:3040/api/registries
# → {"registries":[{"id":"@genicul-primevue/registry","components":[...]}]}
```

The bundled registry ships **five** components: `data-table`, `input-pair`, `result-card`, `city-picker`, and `weather-card`.

::callout{type="tip"}
**Fast path:** `bash examples/playground/start.sh` starts the server (port 3041) and the playground (port 3040) in one command, kills stale processes, writes PID files, and prints the URLs. Use it when you do not want two terminals open.
::

### Start the playground

In a second terminal, from the repo root:

```bash
bun --filter genicui-playground dev
```

Nuxt picks port `3040`. Open the URL it prints.

You should see the three-zone layout:

```
┌──────────────────────────────────────────────────────────┐
│ GenicUI Playground                                ● Conn │
├─────────────┬────────────────────┬───────────────────────┤
│ ConfigPanel │ PromptsPanel       │ ChatPanel             │
│ • Server    │ Suggested Prompts  │ (empty — chips below) │
│ • Provider  │ ─ Data table …     │                       │
│ • Connect   │ ─ Calculator …     │                       │
│ • Registry  │ ─ Weather …        │                       │
│ • Components│                    │                       │
└─────────────┴────────────────────┴───────────────────────┘
```

::callout{type="info"}
The **render surface** is the chat panel, not a fourth column. After F43, every rendered component lives inside a chat bubble as an interactive widget — there is no separate "RenderSurface" card column.
::

### Pick a provider

The left column shows a **Provider** dropdown — the bridge between your chat prompts and an LLM. The default is `claude-code`; the playground spawns the Claude Code CLI as a subprocess and pipes prompts to it.

- **`claude-code`** (default) — spawns the `claude` CLI; `cliPath` defaults to `/opt/homebrew/bin/claude`. Change it if your binary lives elsewhere (`/usr/local/bin/claude` for Intel Homebrew, or just `claude` if it is on `$PATH`).
- **`codex`** — coming soon (disabled in the dropdown).

The selection persists in `localStorage` under the key `genicui-playground:providers:v2`, so the playground remembers it across reloads.

::callout{type="info"}
Provider selection replaces the legacy "API key" field from earlier versions. The playground never sees your Anthropic/OpenAI key directly — the LLM CLI handles its own credentials.
::

### Connect

Click **Connect** in the left column. The top-bar pill transitions `● Disconnected` → `Connecting…` → `● Connected` (with a spinner during the handshake). On success:

- The **Registry** dropdown auto-populates from `/api/registries` (one entry: `@genicul-primevue/registry`).
- The **PromptsPanel** middle column fills with example prompts from the selected registry.
- The **ChatPanel** input bar becomes active.

If the connection refuses, the pill turns red and a banner appears with a **Retry** button. The most common cause is starting the playground before the server. See [Troubleshooting](#troubleshooting) below.

### Click a prompt → render a DataTable

In the **PromptsPanel**, click `Show me a data table with orders`. The prompt is piped through `useChatInput().fillAndSubmit()`, which fills the chat textarea and fires the submit handler. A user bubble appears in the right column with typing dots while the agent is processing.

A few seconds later, the assistant's reply arrives as a chat message containing a `render_component` tool result. The rendered PrimeVue `<DataTable>` is embedded inline in the chat bubble — sortable, paginated, themed by your app's CSS variables.

### Click a row → capture the event

Click any row in the rendered table. The playground emits a `chat.component_event` frame on the `__chat__` channel:

```json
{
  "type": "chat.component_event",
  "componentId": "abc123",
  "name": "row-click",
  "payload": { "rowId": "row-2" }
}
```

The server forwards this to the Claude Code CLI's session as a synthetic tool result. The model's next turn sees the row id and can refer back to it — for example, by typing *"what row did I just click?"*.

::callout{type="tip"}
Looking for the props the server sent with the render? Expand the **Props** `<details>` toggle inside the `ToolCallAccordion` beneath each rendered component in the chat bubble.
::

You have now driven a full GenicUI round-trip: prompt → render → interact → event captured. Every subsequent prompt flows through the same pipeline.
::

## How the playground stays in sync

| Concern | Mechanism |
| --- | --- |
| **Connection state** | `useWebSocket()` singleton; auto-reconnects every 3 seconds for up to 5 retries after a successful first connect. Initial connect failure (server not running) shows an error banner with manual **Retry**. |
| **Rendered surface** | `useComponents()` singleton tracks `MountedComponent[]`; each render pushes onto the array, each `STATE_DELTA` patches the matching component in place. |
| **Chat history** | `useChat()` singleton buffers `chat.message` / `chat.response` / `chat.event` / `chat.complete` / `chat.error` frames. |
| **Prompt → submit** | `useChatInput()` singleton; both the PromptsPanel rows and the bottom ChatInput bar share the same `fillAndSubmit()` path. |
| **Mounted count** | The "Components" pill in the left column reads `components.length` from the singleton. |

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| **`Connection refused — is the GenicUI server running?`** | No server on the configured port. | Start the server (step 2) or update the **Server** field in the playground if it runs elsewhere. The default `ws://localhost:3041/ws` matches the bundled `start.sh`. |
| **`Component "X" not found in catalog`** | Server has no registries loaded. | `GENICUI_REGISTRIES_DIR=./registries bun --filter @genicui/server start` from the repo root. |
| **Registry dropdown is empty** | Server is on, but `/api/registries` returned `[]`. | Same fix as above; confirm the `registries/primevue/` directory exists. |
| **Prompts panel says "This registry has no example prompts"** | The selected registry did not declare `examplePrompts`. | Pick a different registry, or edit its `registry.json` to add prompts. |
| **`bun run dev` complains the port is in use** | Another process holds 3040. | Nuxt falls back to the next free port and prints the chosen URL — use that. |
| **Clicking a prompt does nothing** | The chat input is disabled (disconnected). | Verify the top-bar pill is green (`● Connected`); reconnect if not. |
| **CLI provider errors with `ENOENT`** | The configured `cliPath` does not resolve to a real binary. | Update the **Provider → CLI binary path** field, or set `$GENICUI_CLAUDE_BIN`. |

## Where to next

You now have a working end-to-end GenicUI pipeline. To extend it:

- **Browse every component's props + events** — see the [PrimeVue Registry API](/api/primevue-registry). It documents all five shipped components (`data-table`, `input-pair`, `result-card`, `city-picker`, `weather-card`) verbatim from `registries/primevue/registry.json`, including each event's payload schema.
- **Render from your own backend** — see the [Protocol](/concepts/protocol) and the [`@genicui/agent-bridge`](/api/agent-bridge) API.
- **Drive the same MCP tools from Claude Code directly** — see [Tools → MCP](/concepts/mcp-tools). The playground renders components; Claude Code calls the same four MCP tools.
- **Wrap your own components** — start with [Guides → Custom Registry](/guides/custom-registry) using `@genicul-primevue/registry` as the template, or follow the [Mantine walkthrough](/guides/custom-registry#walkthrough-genicul-mantineregistry) for a worked React example.
- **Ship to production with API keys + trust boundary** — see [Concepts → Trust Boundary](/concepts/trust-boundary).
- **Deploy the server** — see [Deployment → Cloudflare](/deployment/cloudflare) or [Deployment → Bun self-host](/deployment/bun-self-host).
- **Wire your own LLM via the bridge package** — see [`@genicui/agent-bridge`](/api/agent-bridge).
