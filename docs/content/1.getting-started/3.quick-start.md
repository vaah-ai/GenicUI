This walkthrough renders a real `DataTable` component from a Claude Code agent, then captures a `row_selected` event back into the model. Total elapsed time: **under five minutes** on a fresh checkout with Bun installed.

::callout{type="info"}
**Prerequisites:** Bun 1.3.12+, a Claude Code install with the MCP CLI, and `git`. The example uses the bundled PrimeVue registry so you do not need any other UI framework.
::

## The five-minute flow

::steps
### Start the GenicUI server

```bash
git clone https://github.com/vaah-ai/GenicUI.git
cd GenicUI
bun install
bun --filter @genicui/server start
# → Server running at http://0.0.0.0:3040
```

The server boots on port `3040` and auto-loads every registry under `registries/`. The PrimeVue registry ships with the repo, so `DataTable` is available immediately.

Verify the server is healthy:

```bash
curl http://localhost:3040/health
# → {"status":"ok"}
```

### Register the server with Claude Code

Add the GenicUI server as an MCP endpoint. Claude Code discovers the four tools (`find_ui_component`, `render_component`, `update_component`, `subscribe_to_events`) and exposes them to the model.

```bash
claude mcp add genicui \
  --transport http \
  --url http://localhost:3040/mcp \
  --header "Authorization: Bearer dev"
```

::callout{type="warning"}
`Authorization: Bearer dev` is a dev-mode placeholder. In production, set `GENICUI_API_KEY` on the server and pass `Bearer gnc_live_<32-char-key>` from the client. See [Trust Boundary](/concepts/trust-boundary) for production setup.
::

Confirm the registration:

```bash
claude mcp list
# → genicui: http://localhost:3040/mcp (connected)
```

### Open the playground chat surface

The playground at `examples/playground/` is a Nuxt 4 app with a chat panel wired to the same WebSocket.

```bash
bun --filter genicui-playground dev
# → http://localhost:3000
```

Open the URL in your browser. You should see a three-zone layout: registry sidebar, prompt chips, and a chat panel.

### Render a DataTable from a chat prompt

In the playground chat, type:

```text
Render a data table with three rows.
```

The Claude Code agent calls `find_ui_component({ name: "DataTable" })`, then `render_component({ name: "DataTable", props: { rows: [...] } })`. The chat bubble embeds the rendered `<DataTable>` PrimeVue component inline — sortable, paginated, and styled by the playground's theme.

### Click a row → receive the event

Click any row in the rendered table. The browser fires a `row_selected` event back to the GenicUI server, which forwards it to Claude Code as a synthetic tool result. The model's next turn sees:

```json
{
  "action": "row_selected",
  "detail": { "rowId": "row-2" }
}
```

You can verify the event was captured by typing "what row did I just click?" — the agent responds with the row's data.
::

## What just happened

| Step | MCP tool | Result |
|---|---|---|
| Discover | `find_ui_component({ name: "DataTable" })` | Catalog hit — returns schema + events |
| Mount | `render_component({ name, props, idempotencyKey })` | Component mounts, `componentId` returned |
| Wire | `subscribe_to_events({ componentId, events: ["row_selected"] })` | Server starts forwarding events |
| Update | (later) `update_component({ componentId, patch })` | JSON-Patch applied to live instance |
| Capture | (browser → server) | Event frame relayed to agent |

## Verify it worked

If the table did not render, walk down this checklist:

1. **Server is up?** `curl http://localhost:3040/health` returns `{"status":"ok"}`.
2. **MCP is connected?** `claude mcp list` shows `genicui: connected`.
3. **Registry loaded?** `curl http://localhost:3040/api/registries` lists the PrimeVue registry (requires `Authorization` header in production).
4. **Component exists?** From Claude Code, ask "what components are available?" — the agent lists them via `find_ui_component`.
5. **No CORS error?** Open the browser devtools network tab; the WebSocket upgrade at `/ws` should be `101 Switching Protocols`.

::callout{type="error"}
**Symptom:** `Component "DataTable" not found in catalog`.
**Cause:** The registry directory is not on the server's load path.
**Fix:** `GENICUI_REGISTRIES_DIR=./registries bun --filter @genicui/server start` from the repo root.
::
