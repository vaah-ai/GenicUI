Pick the host that matches your traffic profile, ops preference, and existing infrastructure. GenicUI ships the same `@genicui/server` runtime against four targets — three for the runtime, one for this doc site. This page is the decision matrix; the three option pages that follow (Cloudflare, Bun, Nitro) are landing pages linking to the M6 deep dives.

::callout{type="info"}
**Vercel hosts this doc site — it is not a runtime target for GenicUI itself.** The GenicUI runtime choices are Cloudflare Workers, Bun self-host, and the Nitro/Nuxt binding. If you're deploying GenicUI as a product, skip the Vercel column below and pick a runtime row.
::

## Decision matrix

| Target | Best for | Cold start | State store | Setup effort | Trade-off |
|---|---|---|---|---|---|
| **Cloudflare Workers + DO** ([deep dive](/deployment/cloudflare)) | Production, multi-region edge | ~50ms (Workers p95) | Durable Objects SQLite (>1MB) | Medium — `wrangler.toml` + DO migrations | 30s request limit, DO pricing, hibernation semantics |
| **Bun self-host** ([deep dive](/deployment/bun-self-host)) | Dev, CI, single-tenant, on-prem | 0ms (always warm) | In-memory `Map` (MVP); pluggable | Trivial — `bun run start` | You own ops, no auto-scaling, single-region |
| **Nitro/Nuxt binding** ([deep dive](/deployment/nitro)) | Existing Nuxt apps | Inherits host | In-memory, host-store pluggable | Easy — `pnpm add nuxt-genicui` | Tied to Nuxt release cycle; can't run on Workers |
| **Vercel (docs site only)** | This documentation site | (static) | (static, Git) | Trivial — Git push | Not for runtime; static SSG only |

::callout{type="warning"}
**Trade-offs matter more than features.** Each row's right column is what you *give up*. Read it before committing to a target.
::

## Pick one

```
Where will GenicUI run?
├── Multi-region edge in front of users?  → Cloudflare Workers + DO
├── One region, full control, on-prem?    → Bun self-host
└── Already running a Nuxt app?           → Nitro / Nuxt binding
```

If two of these apply (e.g. global + Nuxt), **pick the binding that wins on infrastructure you already operate** — the deeper the integration, the worse the second host performs.

## When the answer is none of these

Three signals point at a host not in the matrix:

- **Need Kubernetes** — wait for the Phase-3 work tracked in the [roadmap](/community/roadmap). Today there is no first-party `Deployment` manifest; community-maintained options live in the [community › contributing](/community/contributing) list.
- **Need a fully managed control plane** — same answer as above. Cloudflare's managed Durable Objects are the closest available; nothing else ships in the MVP.
- **Need to deploy the doc site somewhere other than Vercel** — see the [Vercel deploy guide](/) — the project includes `vercel.json` and an opinionated `nitro` preset, but a Cloudflare Pages or Netlify drop-in is in scope for a follow-up.
