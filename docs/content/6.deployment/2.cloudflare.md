Run GenicUI on Cloudflare's edge network. Cold start p95 ≤ 50ms across the 300+ POPs, state persisted in Durable Object SQLite, WebSocket hibernation keeps sessions alive across restarts. This is the production-grade target chosen for the MVP.

This page is a **landing** — it links to the M6-T1 deep dive that owns the wiring, tests, and operational tools. If you've already decided on Cloudflare, jump straight to the M6-T1 task file; otherwise read the [overview](/deployment/overview) first.

## Architecture

A single Worker handles `/health`, `/ws`, and `/mcp`. Each session maps to one Durable Object instance, identified by `sessionId`. State lives in the DO's SQLite storage (one row per session, mutated in transactions). The [WebSocket Hibernation API](https://developers.cloudflare.com/durable-objects/learning/websockets/) keeps a connection alive across the DO's ~10s inactivity window without dropping the client.

```ts
import { mountGenicUIForWorkers, GenicSessionDO } from '@genicui/server/workers';

export { GenicSessionDO };

export default {
  async fetch(request: Request, env: Env, ctx: ExecutionContext) {
    return mountGenicUIForWorkers({ request, env, ctx, sessionDO: GenicSessionDO });
  },
};

interface Env {
  SESSION: DurableObjectNamespace;
  GENICUI_API_KEY: string;
  GENICUI_LOG_LEVEL: string;
  GENICUI_HEARTBEAT_MS: string;
}
```

::note
**Why a DO per session, not one DO for all sessions?** A single DO would serialize every WebSocket message across all users — defeating the point of edge deployment. Per-session DOs scale horizontally with users and let the runtime pick the closest POP.
::

## Prerequisites

- A Cloudflare account with Workers + Durable Objects enabled
- `wrangler` CLI — `bun install -g wrangler && wrangler login`
- A `gnc_live_<32>` API key — `openssl rand -hex 16`
- A registered DO class via `wrangler.toml` (see the deep-dive for the file)

## Trade-offs

::callout{type="warning"}
**What you give up by choosing Cloudflare Workers:**

- **30-second CPU limit per request.** Long-running inference loops must be split across multiple invocations or moved to [Queue consumers](https://developers.cloudflare.com/queues/). Streaming responses work; blocking waits over ~25s do not.
- **No native TCP / arbitrary ports.** The HTTP and WebSocket surfaces are first-class; raw database connections require a Tunnel or HTTP shim. SQLite via DO storage is the supported path.
- **DO per-request billing.** DO requests are cheap individually, but high-cardinality session creation can add up. Use `wrangler tail` to monitor.
- **Hibernation semantics.** State is durable; in-process state (`let x = ...`) is not. Per-message handlers must rehydrate from `state.storage.sql` on every entry.
- **No filesystem.** Bundling must happen at build time. Dynamic `import()` of unsupported modules fails. The `nodejs_compat` flag covers most Node APIs.

If any of these is a hard blocker, the [Bun self-host](/deployment/bun-self-host) or [Nitro binding](/deployment/nitro) may be a better fit.
::

## Operational tooling

- `wrangler tail` — stream live Worker logs
- `wrangler secret put GENICUI_API_KEY` — rotate the API key without a redeploy
- `wrangler deploy --env production` — promote a built Worker
- DO inspector — list DO instances by ID from the Cloudflare dashboard
