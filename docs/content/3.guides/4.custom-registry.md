This guide walks the five-step process of building a `@genicul-<yourlib>/registry` — the package that turns any component library (PrimeVue, Material, your in-house design system) into a GenicUI surface. The `@genicul-primevue/registry` shipped in M5-T3 is the canonical reference; we'll mirror its layout end-to-end.

::callout{type="info"}
**Why build a registry?** Three benefits stack up: (1) typed props with `additionalProperties: false`, (2) `PassThrough` integration so existing components are wrapped rather than reimplemented, and (3) trust metadata that lets the agent distinguish project-built components from arbitrary npm packages.
::

## The five-step process

::steps{level="3"}
#### Scaffold the package

```bash
mkdir packages/yourlib-registry
cd packages/yourlib-registry
bun init
```

Use the `@genicul-` npm scope (publishing under a different scope is allowed but loses the trust-tier default).

Set up `package.json` with the standard fields — `type: module`, ESM-only, and the `exports` map pointing at `./registry` and `./dist`:

```json
{
  "name": "@genicul-yourlib/registry",
  "version": "0.1.0",
  "type": "module",
  "exports": {
    ".": "./dist/index.js",
    "./registry": "./dist/registry.js",
    "./schema": "./dist/schema.js"
  },
  "dependencies": {
    "@genicul/core": "workspace:*",
    "@sinclair/typebox": "^0.34.0"
  },
  "devDependencies": {
    "@genicul/conformance": "workspace:*",
    "bun-types": "latest"
  }
}
```

#### Implement `defineRegistry()` with `defineComponent()` for each component

The contract is a single exported `registry` object whose `components` array holds one entry per component. Each entry declares its `propsSchema`, `events`, `tags`, and `examples`. The shape mirrors `ComponentEntry` from `@genicui/server`.

```ts
// src/registry.ts
import { Type } from '@sinclair/typebox';

const ButtonProps = Type.Object({
  label: Type.String(),
  variant: Type.Optional(Type.Union([Type.Literal('primary'), Type.Literal('secondary')])),
  disabled: Type.Optional(Type.Boolean()),
}, { additionalProperties: false });

const ButtonEvents = [
  { name: 'click', payloadSchema: Type.Object({ label: Type.String() }, { additionalProperties: false }) },
];

export const Button = {
  name: 'button',
  version: '1.0.0',
  uri: 'ui://components/button@1.0.0',
  propsSchema: ButtonProps,
  framework: 'yourlib@2.0.0',
  tags: ['button', 'action', 'form'],
  events: ButtonEvents,
  examples: [
    { label: 'Save', variant: 'primary' },
    { label: 'Cancel', variant: 'secondary' },
  ],
};

export const registry = {
  id: '@genicul-yourlib/registry',
  version: '0.1.0',
  framework: 'yourlib',
  components: [Button /*, Input, Card, ... */],
};
```

::callout{type="warning"}
**`additionalProperties: false` is not optional.** Every `propsSchema` object and every `events[].payloadSchema` object must set it. The trust boundary rejects registries that omit it — see [Trust Boundary](/concepts/trust-boundary).
::

#### Declare a trust tier in `registry.json`

The trust tier is a runtime config that the server reads at boot. `project` is the safest default — only loaded when the project's own code references it. `user` is for explicitly opted-in packages. `remote` requires the most scrutiny and is gated behind the `GENICUI_REGISTRY_ALLOWLIST` env var.

```json
// registry.json (companion to the JS export)
{
  "id": "@genicul-yourlib/registry",
  "version": "0.1.0",
  "framework": "yourlib",
  "trustTier": "project",
  "components": ["button", "input", "card"]
}
```

#### Add per-event `detailSchema` and lifecycle hooks

For every event declared in `events[]`, the component must declare a `payloadSchema` matching the `detail` it dispatches. Components are responsible for emitting events with `composed: true` so they cross the closed Shadow DOM boundary — see [Events](/concepts/events).

```ts
// In your Web Component subclass
this.dispatchEvent(new CustomEvent('click', {
  detail: { label: this.props.label },
  bubbles: true,
  composed: true,
}));
```

#### Test with `@genicui/conformance`

The conformance runner is a hard gate before publishing:

```ts
// src/registry.test.ts
import { describe, it, expect } from 'bun:test';
import { runConformance } from '@genicui/conformance';
import { registry } from './registry.js';

describe('registry conformance', () => {
  it('passes the 5-rule conformance suite', async () => {
    const result = await runConformance(registry, {
      framework: 'vanilla',
      mountPoint: '#test-root',
    });
    expect(result.failures).toEqual([]);
  });
});
```

CI runs this on every PR that touches `registries/**` — a merge to `main` is blocked until conformance is green.
::

## Walkthrough — `@genicul-primevue/registry`

The shipped PrimeVue registry is the reference implementation. It exports five components — `DataTable`, `InputPair`, `ResultCard`, `CityPicker`, `WeatherCard` — each with a TypeBox schema, an events array, and examples.

```ts
// registries/primevue/src/registry.ts (excerpt)
import { DataTableSchema } from './data-table-schema.js';
import { DataTableEvents } from './data-table-events.js';

export const DataTable = {
  name: 'data-table',
  version: '1.0.0',
  uri: 'ui://components/data-table@1.0.0',
  propsSchema: DataTableSchema,
  framework: 'primevue@4.2.0',
  tags: ['table', 'data', 'grid', 'rows', 'pagination', 'sort', 'filter'],
  events: DataTableEvents,
  examples: [
    {
      rows: [
        { id: '1', name: 'Alice', status: 'active' },
        { id: '2', name: 'Bob', status: 'inactive' },
      ],
      columns: [
        { key: 'name', label: 'Name', sortable: true },
        { key: 'status', label: 'Status', sortable: true, filterable: true },
      ],
      pageSize: 10,
      page: 0,
    },
  ],
};

export const registry = {
  id: '@genicul-primevue/registry',
  version: '0.2.0',
  framework: 'primevue',
  components: [DataTable, InputPair, ResultCard, CityPicker, WeatherCard],
};
```

Two patterns to lift directly:

1. **Schema modules separate from registry.** `data-table-schema.ts`, `data-table-events.ts` live next to the entry — easy to find and conformance-walk in isolation.
2. **Examples carry default values.** The agent uses `examples[]` to seed props when the user request is ambiguous. Two example rows in the PrimeVue registry are why `find_ui_component` returns it for a bare *"show a table"* prompt.

## Publishing

```bash
# 1. Verify the workspace builds
bun --filter @genicul-yourlib/registry build

# 2. Run conformance locally
bun --filter @genicul-yourlib/registry test

# 3. Bump and publish
bun pm version 0.1.0
bun publish --access public
```

Publishing to npm with the `@genicul-` scope gives you the default trust-tier treatment. Private registries (GitHub Packages, Verdaccio) work the same way — set `registry=` in `.npmrc` and the same `bun publish` flow applies.

::callout{type="tip"}
**Versioning for compatibility.** Bump the package's minor version when you add a component. Bump the major when you change a `propsSchema`'s required keys or remove a component. The trust boundary's schema check is strict — incompatible versions of `propsSchema` will fail validation at render time.
::

## Verification

Install the freshly published registry into the playground and prove the full round-trip:

```bash
bun add @genicul-yourlib/registry --filter genicui-playground
bun --filter genicui-playground dev
```

Then, from any MCP client:

::steps{level="3"}
#### Mount a component

```bash
curl -X POST http://localhost:3040/mcp \
  -H "Authorization: Bearer $GENICUI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"render_component","arguments":{"name":"button","props":{"label":"Save","variant":"primary"}}}}'
# expect: {"result":{"componentId":"btn-..."}}
```

#### Trigger the click event from the browser

Open the playground, click the button. The Web Component dispatches `click` with `composed: true`.

#### Receive the event on the agent side

From an MCP-inspector or a subscribed WebSocket client:

```json
{"v":1,"channel":"btn-...","type":"COMPONENT_EVENT","payload":{"action":"click","detail":{"label":"Save"}},"seq":42}
```

If the round-trip works, the registry is correctly wired end-to-end.
::
