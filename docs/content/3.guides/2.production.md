This guide is the **deploy-time gate** for GenicUI. It maps the 10-item pre-deploy list from this [production checklist section](#the-10-item-checklist) to the exact commands that satisfy each one, plus the env-var reference, secrets policy, and observability hooks you need before serving the first production request.

::callout{type="warning"}
**The 10-item checklist is non-negotiable.** Every item maps to a security or reliability invariant that the trust boundary relies on. Skipping any one of them silently downgrades the system.
::

## The 10-item checklist

Run through these in order. Each item is a binary pass/fail — there is no partial credit.

::steps{level="3"}
#### Rotate the API key from `gnc_test_*` to a fresh `gnc_live_*`

```bash
openssl rand -hex 16
# paste into GENICUI_API_KEY on the deploy target
wrangler secret put GENICUI_API_KEY  # Cloudflare
# or: set it in your container/PM2/.env.production
```

::callout{type="info"}
**Why `openssl rand -hex 16`?** That's 32 hex chars = 128 bits of entropy, matching the `gnc_live_<32>` shape the server validates against.
::

#### Configure the CORS allowlist

Set `GENICUI_CORS_ORIGINS` to a comma-separated list of HTTPS origins. Never use `*` in production — the WebSocket upgrade requires a matched `Origin` header.

#### Enable WebSocket origin validation

WS upgrade requests are rejected unless `Origin` matches one of the allowlist entries above. This is on by default — verify your reverse proxy forwards `Origin` (Nginx: `proxy_pass_request_headers on;`).

#### Verify the trust boundary's `stripProtoKeys`

Run a smoke call against `/mcp` with a payload containing `__proto__`, `constructor`, or `prototype` keys:

```bash
curl -X POST http://your-host/mcp \
  -H "Authorization: Bearer $GENICUI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"render_component","arguments":{"name":"data-table","props":{"__proto__":"x"}}}}'
# expect: {"error":{"code":-32003,"message":"props_invalid"}}
```

A `-32003` confirms the trust boundary is enforcing. A successful render means the stripper is misconfigured.

#### Wire observability — logs, metrics, traces

GenicUI emits structured JSON to stdout (12-factor). Pipe to your aggregator:

```yaml
# docker-compose.yml excerpt
logging:
  driver: json-file
  options:
    max-size: "10m"
    max-file: "3"
```

For Prometheus, expose `/metrics` (opt-in via `GENICUI_METRICS_ENABLED=true`). For distributed traces, the OpenTelemetry SDK is initialized when `OTEL_EXPORTER_OTLP_ENDPOINT` is set.

#### Move secrets out of `.env` files

`.env` belongs in `.gitignore`. Production secrets belong in:

- Cloudflare: `wrangler secret put ...`
- AWS / GCP: the platform's secret manager
- Kubernetes: sealed-secrets or external-secrets-operator

The server reads env vars on boot — it does not care where they came from.

#### Expose the health-check endpoint

```bash
curl https://your-host/health
# {"status":"ok"}
```

Point your load balancer's health probe at this URL. The endpoint is unauthenticated by design — it never returns session state.

#### Configure persistent session storage

The MVP `memory` store loses sessions on restart. For production:

- **Cloudflare Workers:** Durable Objects (default for `wrangler deploy`)
- **Bun self-host:** SQLite or Postgres (`GENICUI_SESSION_STORE=postgres`)
- **Nitro:** the parent app's existing storage

::callout{type="warning"}
**Backups.** Durable Objects' SQLite is replicated to the region automatically. Postgres is on you — wire `pg_dump` to your backup schedule before going live.
::

#### Terminate TLS at the edge

The server speaks plain HTTP/WS behind a TLS terminator. Cloudflare Workers terminate at the edge automatically; for Bun self-host, use Caddy or Nginx with certbot:

```caddyfile
your-host.com {
  reverse_proxy localhost:8080
  encode zstd gzip
}
```

#### Plan for rate limiting (post-MVP)

The MVP ships rate-limit **hooks** but no enforcement. Before exposing a public endpoint, front GenicUI with Cloudflare WAF rules, Nginx `limit_req`, or your API gateway's policy. Per-API-key buckets need the upcoming `rate-limit-hooks` feature (tracked in the roadmap).
::

## Env var reference

| Var | Required | Default | Notes |
|---|---|---|---|
| `GENICUI_API_KEY` | **yes** | (random in dev) | `gnc_live_<32>` chars. Generate via `openssl rand -hex 16`. |
| `GENICUI_SESSION_STORE` | optional | `memory` | One of `memory` (MVP), `durable-object` (CF), `postgres` (Phase 2) |
| `GENICUI_PORT` | optional | `8080` (Bun) / `3040` (dev) | Bun self-host only |
| `GENICUI_LOG_LEVEL` | optional | `info` | `debug`, `info`, `warn`, `error` |
| `GENICUI_HEARTBEAT_MS` | optional | `30000` | WebSocket ping interval |
| `GENICUI_CORS_ORIGINS` | **prod** | `*` (dev only) | Comma-separated allowlist |
| `GENICUI_REGISTRY_ALLOWLIST` | **prod** | (any) | Comma-separated `package@version` patterns |
| `GENICUI_METRICS_ENABLED` | optional | `false` | Expose `/metrics` |
| `GENICUI_REGION` | optional | (auto) | Phase 2; `eu`, `us`, `apac` |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | optional | (unset) | When set, OTel SDK initializes |

## Secrets policy

- **Never commit a real key.** `.env` files are `.gitignore`'d; CI uses `wrangler secret` / repo secrets.
- **Rotate every 90 days minimum** and immediately on any suspected exposure.
- **Scope per environment.** A key leak in staging should not affect production — use separate keys per target.
- **Log scrubbing is built-in.** The structured logger redacts `gnc_live_*` patterns from any log line. Verify with `bun test packages/server/src/auth/__tests__/log-scrub.test.ts`.

## Observability

GenicUI emits one JSON object per line on stdout. Schema:

```json
{"ts":"2026-09-10T12:34:56.789Z","level":"info","channel":"dt-sess9f8e","event":"render_component","duration_ms":12,"componentId":"dt-abc12301HK9X"}
```

| Event | When | Useful for |
|---|---|---|
| `server.hello` | WS upgrade accepted | Connection-rate dashboard |
| `render_component` | Tool call succeeded | Per-component latency p50/p99 |
| `STATE_DELTA` | Patch dispatched | Patch volume / hot-component detection |
| `COMPONENT_EVENT` | User action crossed wire | Interaction funnel |
| `auth.rejected` | 401 returned | Brute-force detection |

For Prometheus scraping, set `GENICUI_METRICS_ENABLED=true` and point your scraper at `/metrics`. Default metrics: `genicui_render_duration_seconds`, `genicui_ws_connections`, `genicui_patch_apply_total`.

## Verification

Before flipping DNS, run the **production smoke test**:

::steps{level="3"}
#### Render — confirm a component mounts

```bash
curl -X POST https://your-host/mcp \
  -H "Authorization: Bearer $GENICUI_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"tools/call","params":{"name":"render_component","arguments":{"name":"data-table","props":{"rows":[{"id":"1","name":"Alice"}],"columns":[{"key":"name","label":"Name"}]}}}}'
# expect: {"result":{"componentId":"dt-..."}}
```

#### Update — confirm patches dispatch

From a WS client, verify `STATE_DELTA` arrives within 100ms of an `update_component` call.

#### Event — confirm user actions round-trip

Mount an interactive component (e.g. `data-table`), click a row, confirm the agent-side receives `COMPONENT_EVENT` with `payload.detail.rowId`.

#### Health — confirm probes pass

```bash
curl -fsS https://your-host/health
# {"status":"ok"}
```

If all four pass and the 10-item checklist is green, you're production-ready.
::
