This guide walks through the local GenicUI inner loop — clone, install, start the playground, attach an MCP-capable client, and confirm a working render. By the end you should have the server running on `localhost:3040`, the playground mounted in a browser, and four MCP tools visible in your client.

::note
If you just want to consume GenicUI from your own app, [Getting Started → Quick Start](/getting-started/quick-start) is faster — this guide is for **contributors** working inside the monorepo.
::

## Prerequisites

| Tool | Minimum | Verify with |
|---|---|---|
| Bun | 1.3.12 | `bun --version` |
| Git | 2.40+ | `git --version` |
| An MCP-capable client | — | Claude Code, Cursor, or `mcp-inspector` |

::callout{type="info"}
**About ports:** the default server port is `3040` (set in `packages/server/src/config.ts`). If `3040` is busy, the server picks the next free port and logs it — read the boot banner before connecting.
::

## Clone and install

::steps{level="3"}
#### Clone the repository

```bash
git clone https://github.com/your-org/genicui.git
cd genicui
```

#### Install workspace dependencies

```bash
bun install
```

Bun resolves the full workspace (`packages/*`, `registries/*`, `examples/*`) in one pass. A clean install takes 20–40 seconds.

#### Sanity-check the install

```bash
bun pm ls
```

You should see `@genicui/core`, `@genicui/server`, `@genicui/client`, `@genicui/vite-plugin`, `@genicui/agent-bridge`, and `@genicul-primevue/registry` in the tree. No `@nuxt/ui-pro` — the playground uses `@nuxt/ui` v4 MIT.
::

## Start the server

The production launcher is `packages/server/start.sh`. From the repo root:

```bash
bun --filter @genicui/server start
```

You should see a banner like:

```text
@genicui/server listening on http://localhost:3040
MCP endpoint: http://localhost:3040/mcp
WebSocket:    ws://localhost:3040/ws
```

If the port is in use, the server increments to the next free port — check the banner for the actual URL.

## Start the playground

The playground is the canonical demo app from M5-T4. It runs Nuxt 4 + the PrimeVue registry on a different port (default `3000`).

```bash
bun --filter genicui-playground dev
```

Open `http://localhost:3000` — you'll see a three-zone layout (sidebar + chat + render surface). The chat panel already has an MCP connection to the server above; sending a message like *"render a data table of 5 cities"* should produce a `<genic-data-table>` in the right-hand column.

## Connect your own MCP client

The server exposes four MCP tools over Streamable HTTP at `/mcp`. To connect a separate client:

::code-group
```json [Claude Code (.mcp.json)]
{
  "mcpServers": {
    "genicui-dev": {
      "type": "http",
      "url": "http://localhost:3040/mcp",
      "headers": {
        "Authorization": "Bearer gnc_live_<32-char-key>"
      }
    }
  }
}
```

```bash [mcp-inspector]
npx @modelcontextprotocol/inspector \
  --url http://localhost:3040/mcp \
  --header "Authorization: Bearer gnc_live_<32-char-key>"
```
::

The dev server prints the auto-generated API key on every boot (`GENICUI_API_KEY`). Copy it from the server log — never check a real key into git.

::callout{type="warning"}
**Test keys only.** The dev launcher generates `gnc_live_<random>` keys for convenience — these are still production-shaped, but never use them outside `localhost`. See [Production](/guides/production) for the rotation policy.
::

## Hot reload

The server runs under Bun's `--hot` flag, which watches `packages/server/src/**` and `registries/**`. Edit any file and the process restarts in place:

```bash
# Edit packages/server/src/mcp/render-component.ts
# Save — Bun restarts the server in ~200ms
# WS clients reconnect automatically (F33 session recovery)
```

For the **client package**, edit any file in `packages/client/src/` and the Vite dev server hot-reloads the playground page without a full reload.

## Run the test suite

A full test pass takes under 60 seconds and is the fastest way to confirm your install is healthy:

```bash
bun test                    # ~150 unit + 20 integration
bun test --coverage         # adds the coverage gate (~90s)
```

See [Testing](/guides/testing) for the full pyramid and per-layer commands.

## Verification

You should now have four observable outcomes:

1. **`curl http://localhost:3040/health` returns `{"status":"ok"}`** — server is up.
2. **The playground at `http://localhost:3000` shows the three-zone layout** — Nuxt is serving.
3. **Your MCP client lists four tools** (`find_ui_component`, `render_component`, `update_component`, `subscribe_to_events`) — Streamable HTTP auth succeeded.
4. **`bun test` exits 0** — the workspace installed cleanly.

If any of these fail, the most common culprit is port contention (`lsof -i :3040`) or a stale API key from a previous server run.
