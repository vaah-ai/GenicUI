A **registry** is an npm package that declares a set of components — their schemas, events, tags, and runtime adapters. GenicUI loads one or more registries at boot, validates every schema, and merges them into a single in-memory catalog. This page is the registry contract reference: the shape of a component entry, the URI grammar that identifies it, and the resolution order that wins on conflicts.

## The registry contract

`Source: .vaahagents/requirements/specs/features/feature-037-component-registry.md` (F37)

A registry exports a single object via `defineRegistry()`. Each component entry declares everything the agent needs to discover, validate, and render it.

```ts
import { defineRegistry, defineComponent } from '@genicui/core';

const DataTable = defineComponent({
  name: 'data-table',
  version: '1.0.0',
  description: 'Server-paginated table with sortable headers and per-column filters.',
  propsSchema: {
    type: 'object',
    properties: {
      rows: { type: 'array' },
      columns: { type: 'array' },
      pageSize: { type: 'integer', default: 25 },
    },
    required: ['rows', 'columns'],
    additionalProperties: false,
  },
  tags: ['table', 'sortable', 'filterable'],
  events: [
    {
      name: 'row_selected',
      payloadSchema: {
        type: 'object',
        properties: { rowId: { type: 'string' } },
        required: ['rowId'],
        additionalProperties: false,
      },
    },
  ],
  examples: [
    {
      rows: [{ id: '1', name: 'Alice' }],
      columns: [{ key: 'name', label: 'Name' }],
    },
  ],
  whenToUse: 'Use this whenever the user wants to see a list of structured records.',
});

export const primevueRegistry = defineRegistry({
  library: '@genicul-primevue/registry',
  version: '1.0.0',
  components: [DataTable],
});
```

The locked contract — every entry must have these fields:

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `name` | string | ✅ | Registry-unique kebab-case name. |
| `version` | semver | ✅ | Pinned via npm version. |
| `description` | string | ✅ | One-line summary shown to the agent. |
| `propsSchema` | JSON Schema | ✅ | Must include `additionalProperties: false`. |
| `tags` | string[] | optional | Discovery hints for `find_ui_component`. |
| `events` | `EventEntry[]` | ✅ | Every event the component emits. |
| `examples` | `object[]` | ✅ | At least one valid props example. |
| `whenToUse` | string | optional | Agent-facing directive — phrased as an instruction. |

## `ui://` URI grammar

`Source: .vaahagents/requirements/specs/features/feature-024-ui-resource-grammar.md` (F24). Two URI namespaces identify components on the wire:

| Pattern | Type | Example |
|---------|------|---------|
| `ui://genicul/{lib}/{comp}` | **Catalog** | `ui://genicul/primevue/data-table` |
| `ui://genicul/{lib}/{comp}@{version}` | **Catalog pinned** | `ui://genicul/primevue/data-table@1.0.0` |
| `ui://instance/{sessionId}/{componentId}` | **Live instance** | `ui://instance/sess-9f8e7d/dt-sess9f8e-01HK9X` |

**Catalog URIs** resolve to the component's metadata — schema, examples, whenToUse — returned via MCP's `resources/read`:

```json
{
  "uri": "ui://genicul/primevue/data-table",
  "mimeType": "application/vnd.genicul.component+json",
  "text": "{ \"schema\": {...}, \"whenToUse\": \"...\", \"examples\": [...] }"
}
```

**Instance URIs** resolve to the live Web Component HTML, served for iframe-mode adapters and SSR previews:

```json
{
  "uri": "ui://instance/sess-9f8e7d/dt-sess9f8e-01HK9X",
  "mimeType": "text/html",
  "text": "<genic-data-table component-id=\"dt-sess9f8e-01HK9X\" props-json=\"...\"></genic-data-table>"
}
```

Malformed URIs return MCP's standard `resource not found` error. There is no partial match — `ui://genicul/primevue` (no component) is invalid.

## Trust tiers and resolution order

`Source: .vaahagents/requirements/specs/features/feature-038-registry-trust-tiers.md` (F38). GenicUI loads registries from three tiers:

| Tier | Source | Path | Allow-list? |
|------|--------|------|-------------|
| **Project** | Repo-local manifest | `./registry.json` or `registries/` directory | No — always trusted |
| **User** | User home directory | `~/.config/genicui/registry.json` | No |
| **Remote** | HTTP registry server | `https://<registry-host>/api/components` | **Yes** — `GENICUI_REGISTRY_ALLOWLIST` |

Resolution order: **Project > User > Remote**. When two tiers define the same component URI, the higher tier wins:

```text
Project registry:  data-table@1.0.0 (custom props)
User registry:     data-table@2.0.0
Remote registry:   data-table@2.0.0 (official)
                   ─────────────────
Effective:         data-table@1.0.0 (project wins)
```

Remote entries are filtered by `GENICUI_REGISTRY_ALLOWLIST`. The default allow-list is `@genicul-primevue/registry` only. Entries outside the allow-list are dropped with a log warning — they never enter the effective registry.

::callout{type="info"}
The Phase 2 release adds `GENICUI_REGISTRY_ALLOWLIST` as an enforced env var. The MVP ships the loader and the resolution order; enforcement is gated on the operator setting the env var.
::

## Install flow

::steps
### Install the npm package

```bash
bun add @genicul-primevue/registry
```

The package's `package.json` declares `main` (or `exports`) pointing to its compiled entry. No global registration is needed — the package is just code.

### Load at server boot

```ts
// Source: examples/playground/server/index.ts
import { loadRegistry } from '@genicui/server';
import { primevueRegistry } from '@genicul-primevue/registry';

await loadRegistry(primevueRegistry);
```

`loadRegistry()` validates every component's `propsSchema` (rejects open schemas), walks the schema tree for `additionalProperties: false`, and registers events. Failure to load throws — the server refuses to boot.

### Hot reload on `SIGHUP`

Send `SIGHUP` to the running server and it re-loads the registry without dropping open WebSocket connections:

```bash
kill -HUP $(pgrep -f genicui-server)
```

Existing channels stay open; new `find_ui_component` calls see the updated catalog. F37-AC3 enforces this.

### Discover via `find_ui_component`

```json
{ "name": "find_ui_component", "arguments": { "capability": "table", "tags": ["sortable"] } }
```

→ Returns `ui://genicul/primevue/data-table` with the schema, examples, and `whenToUse`.

### Render via `render_component`

```json
{ "name": "render_component", "arguments": { "name": "DataTable", "props": {...} } }
```

→ Returns the `componentId` + channel + live component HTML.
::

## PassThrough API integration (PrimeVue 4)

`Source: .vaahagents/requirements/specs/features/feature-040-primevue-registry.md` (F40). PrimeVue 4 exposes a PassThrough (`pt`) API that lets registries hook into the framework without DOM probing. GenicUI uses it to wire event handlers and props on the underlying PrimeVue components:

```ts
// Source: registries/primevue/src/data-table.ts
import PrimeVueDataTable from 'primevue/datatable';
import { GenicElement } from '@genicui/runtime';

class DataTableElement extends GenicElement {
  private primevue: PrimeVueDataTable;

  connectedCallback() {
    super.connectedCallback();
    this.primevue = new PrimeVueDataTable({
      pt: {
        root: { class: 'genic-data-table' },
        table: { 'aria-label': this.getAttribute('aria-label') ?? 'Data table' },
      },
      onRowSelect: (e) => this.dispatchEvent(
        new CustomEvent('row_selected', { detail: e.data, bubbles: true, composed: true }),
      ),
    });
  }

  onPatch(patches: JsonPatchOp[]) {
    for (const op of patches) {
      const [key, value] = applyOp(this.props, op);
      this.primevue.setProp(key, value);
    }
  }
}

customElements.define('genic-data-table', DataTableElement);
```

The PassThrough object is the contract surface. The runtime never touches PrimeVue's DOM — PrimeVue re-renders itself when its props change.

## The 8-prop `gv-data-table` API

PrimeVue's DataTable ships 30+ props. The GenicUI wrapper reduces the agent-facing API to 8:

| Prop | Type | Purpose |
|------|------|---------|
| `rows` | `object[]` | The data rows. |
| `columns` | `{ key, label }[]` | Column definitions. |
| `pageSize` | `number` | Items per page. |
| `page` | `number` | Current page (0-indexed). |
| `sort` | `{ key, direction }` | Current sort. |
| `filters` | `Record<string, unknown>` | Per-column filters. |
| `selection` | `string[]` | Selected row IDs. |
| `loading` | `boolean` | Show loading state. |

Events: `row_selected`, `sort_change`, `filter_change`, `page_change`, `selection_change`. The 8-prop API is the agent's only surface — `lazy`, `virtualScroller`, `paginatorTemplate`, etc. are hidden.

## Open-schema rejection at load

Registries with any `additionalProperties: true` schema fail to boot:

```text
[bootstrap] ERROR: Registry validation failed for "@genicul-X/registry":
  components[0].propsSchema.additionalProperties is true (forbidden)

[bootstrap] Refusing to start. Fix the schema or pin a different version.
```

The check is recursive — every nested `object` in `props.properties.*` and `items.*` is walked. A single open schema anywhere in the tree fails the load.
