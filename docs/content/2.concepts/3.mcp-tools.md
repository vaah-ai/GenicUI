GenicUI exposes exactly four public MCP tools. They are the entire wire protocol from the agent's perspective — every render, update, and event subscription flows through one of them. Each tool's `inputSchema` is emitted with `additionalProperties: false`, and the server validates every call against the locked contract before any state mutates.

## Tool catalog

::tabs
:::tab{label="find_ui_component" icon="i-lucide-search"}
Resolve a UI capability to a `ui://` resource.

```json
{ "capability": "table", "tags": ["sortable", "filterable"] }
```

Returns the catalog entry (schema + examples + events) so the agent can `resources/read` it.
:::

:::tab{label="render_component" icon="i-lucide-package-plus"}
Mount a component on a connected client.

```json
{ "name": "DataTable", "props": { "rows": [...], "pageSize": 10 }, "surface": "default" }
```

Returns a `componentId` and channel. Server emits `STATE_SNAPSHOT` + `COMPONENT_MOUNTED` on that channel.
:::

:::tab{label="update_component" icon="i-lucide-refresh-cw"}
Apply RFC 6902 patches or merge a partial state.

```json
{ "componentId": "dt-...", "patches": [{ "op": "replace", "path": "/rows/1/name", "value": "Alicia" }] }
```

Server emits `STATE_DELTA` with the applied op list. Falls back to `STATE_SNAPSHOT` if patches fail.
:::

:::tab{label="subscribe_to_events" icon="i-lucide-bell"}
Receive user-driven events from a mounted component.

```json
{ "componentId": "dt-...", "events": ["row_selected"] }
```

Server returns a `subscriptionId` and starts forwarding matching `COMPONENT_EVENT` frames.
:::
::

## Error codes

Every GenicUI tool error occupies the namespace `-32001` through `-32010`. Standard MCP errors (`-32700` parse, `-32600` invalid request, `-32601` method not found, `-32603` internal) are honored but not GenicUI-specific.

| Code | Name | When |
|------|------|------|
| `-32001` | `component_not_found` | URI / componentId is unknown to the registry. |
| `-32002` | `surface_unavailable` | Reserved channel name (`__session__`, `__mcp__`, `__agent__`). |
| `-32003` | `props_invalid` | Props fail TypeBox validation. Includes `data.details[]` with field paths. |
| `-32004` | `patch_invalid` | Patch op targets a path that doesn't exist in current state. |
| `-32005` | `event_unknown` | Subscription `events` filter names an event the component doesn't emit. |
| `-32006` | `subscription_not_found` | `unsubscribe` references a missing `subscriptionId`. |
| `-32007` | `idempotency_conflict` | Reused `clientRequestId` with different params. |
| `-32008` | `surface_unavailable` | Channel cap reached or reserved channel reused. |
| `-32009` | `version_drift` | Component version drift > 2 minor versions. |
| `-32010` | `internal` | Unrecoverable internal error. Retry is futile; escalate. |

`Source: packages/server/src/mcp/error-codes.ts` defines the enum. Each error includes a `data` object with diagnostic context the agent can use to recover.

## `find_ui_component`

`Source: .vaahagents/requirements/specs/features/feature-015-find-ui-component-tool.md` (F15)

Resolves a UI capability to a single `ui://` resource. Returns the catalog entry with full schema, examples, and event list so the agent can read it back via MCP's `resources/read`.

### Input schema

```ts
{
  capability: string;       // semantic query, e.g. "table", "form", "chart"
  tags?: string[];          // optional tag filter (intersection)
  topK?: number;            // max results (default 1, max 5)
}
```

### Output schema

```ts
{
  uri: string;              // "ui://components/data-table@1.0.0"
  name: string;             // "DataTable"
  version: string;          // semver
  description: string;
  propsSchema: JSONSchema;  // additionalProperties: false
  events: string[];
  examples: object[];
}
```

### Example

::code-group
```json [Request]
{ "name": "find_ui_component", "arguments": { "capability": "table", "tags": ["sortable"], "topK": 1 } }
```

```json [Response — exact match]
{
  "uri": "ui://components/data-table@1.0.0",
  "name": "DataTable",
  "version": "1.0.0",
  "description": "Server-paginated table with sortable headers and per-column filters.",
  "propsSchema": {
    "type": "object",
    "properties": {
      "rows": { "type": "array" },
      "columns": { "type": "array" },
      "pageSize": { "type": "integer", "default": 25 }
    },
    "required": ["rows", "columns"],
    "additionalProperties": false
  },
  "events": ["row_selected", "sort_change", "filter_change"],
  "examples": [{ "rows": [{ "id": "1", "name": "Alice" }], "columns": [{ "key": "name", "label": "Name" }] }]
}
```

```json [Response — no match]
{ "results": [], "reason": "no_component_matches" }
```

```json [Response — ambiguous]
{ "results": [], "disambiguation": [
  { "uri": "ui://components/data-table@1.0.0", "tags": ["sortable", "filterable"] },
  { "uri": "ui://components/grid@1.2.0", "tags": ["filterable", "virtualized"] }
] }
```
::

### Failure modes

- **Empty match** — server returns `{ results: [], reason: 'no_component_matches' }` instead of an error. The agent should broaden the `capability` or drop `tags`.
- **Ambiguous match** — server returns a `disambiguation` array listing every candidate. The agent picks one and retries with a more specific tag.

## `render_component`

`Source: .vaahagents/requirements/specs/features/feature-016-render-component-tool.md` (F16)

Validates props against the component's TypeBox schema, allocates a fresh `componentId` + channel, and emits `STATE_SNAPSHOT` followed by `COMPONENT_MOUNTED`. The tool returns once the mount has been emitted; the client's Web Component upgrade happens out-of-band.

### Input schema

```ts
{
  name: string;             // component name (registry-resolved)
  props: object;            // matches the resolved schema
  surface?: string;         // default "default"; multi-surface mounting
  clientRequestId?: string; // idempotency key (UUID v4)
  componentVersion?: string; // pinned version; default = latest
}
```

### Output schema

```ts
{
  componentId: string;      // "dt-sess9f8e-01HK9X"
  channel: string;          // mirrors componentId
  schema: JSONSchema;       // resolved schema (for the agent's records)
  events: string[];         // emitted events the agent may subscribe to
}
```

### Example

::code-group
```json [Request]
{
  "name": "render_component",
  "arguments": {
    "name": "DataTable",
    "props": {
      "rows": [{ "id": "1", "name": "Alice" }],
      "columns": [{ "key": "name", "label": "Name" }],
      "pageSize": 10
    },
    "surface": "default",
    "clientRequestId": "r-1"
  }
}
```

```json [Response]
{
  "componentId": "dt-sess9f8e-01HK9X",
  "channel": "dt-sess9f8e-01HK9X",
  "schema": { "type": "object", "additionalProperties": false, "...": "..." },
  "events": ["row_selected", "sort_change", "filter_change"]
}
```

```json [Error — props_invalid]
{
  "isError": true,
  "content": [{
    "type": "text",
    "text": "{\"code\":-32003,\"message\":\"props_invalid\",\"data\":{\"details\":[\"required: rows\"]}}"
  }]
}
```
::

### Failure modes

- `-32003 props_invalid` — props fail TypeBox validation. Includes `data.details[]` with field paths.
- `-32001 component_not_found` — `name` is not in the registry.
- `-32008 surface_unavailable` — channel cap reached.
- `-32007 idempotency_conflict` — `clientRequestId` reused with different params.

### Idempotency

Pass `clientRequestId: "<uuid>"` and the server caches the response for 24 hours. Retries with the same id return the original `componentId` without re-mounting — see [Frames › Idempotency keys](/concepts/frames#idempotency-keys).

## `update_component`

`Source: .vaahagents/requirements/specs/features/feature-017-update-component-tool.md` (F17)

Accepts either `patches` (RFC 6902 JSON-Patch) or `mode: 'replace'` with full props. The server diffs current state vs new state, validates, and emits either `STATE_DELTA` or `STATE_SNAPSHOT` (when patches fail or full replacement is requested).

### Input schema

```ts
{
  componentId: string;
  patches?: JsonPatchOp[];          // discriminated union: patches XOR mode
  mode?: 'replace';                 // full snapshot replacement
  props?: object;                   // required when mode = 'replace'
  clientRequestId?: string;
}
```

### Output schema

```ts
{
  componentId: string;
  channel: string;
  applied: boolean;                 // false → server fell back to STATE_SNAPSHOT
  diff: {
    patched?: JsonPatchOp[];        // applied ops (success path)
    snapshot?: object;              // full state (fallback path)
  };
}
```

### Example — patches (primary)

::code-group
```json [Request]
{
  "name": "update_component",
  "arguments": {
    "componentId": "dt-sess9f8e-01HK9X",
    "patches": [
      { "op": "replace", "path": "/rows/0/name", "value": "Alicia" },
      { "op": "add", "path": "/rows/-", "value": { "id": "2", "name": "Bob" } }
    ]
  }
}
```

```json [Response]
{
  "componentId": "dt-sess9f8e-01HK9X",
  "channel": "dt-sess9f8e-01HK9X",
  "applied": true,
  "diff": {
    "patched": [
      { "op": "replace", "path": "/rows/0/name", "value": "Alicia" },
      { "op": "add", "path": "/rows/1", "value": { "id": "2", "name": "Bob" } }
    ]
  }
}
```
::

### Example — replace (full snapshot)

::code-group
```json [Request]
{
  "name": "update_component",
  "arguments": {
    "componentId": "dt-sess9f8e-01HK9X",
    "mode": "replace",
    "props": { "rows": [{ "id": "1", "name": "Alice" }], "columns": [], "pageSize": 25 }
  }
}
```

```json [Response]
{
  "componentId": "dt-sess9f8e-01HK9X",
  "channel": "dt-sess9f8e-01HK9X",
  "applied": true,
  "diff": { "snapshot": { "rows": [...], "columns": [], "pageSize": 25 } }
}
```
::

### Failure modes

- `-32004 patch_invalid` — patch op targets a path not in current state.
- `-32003 props_invalid` — `mode: 'replace'` props fail TypeBox validation.
- `-32001 component_not_found` — `componentId` is not currently mounted.
- Both `patches` and `mode: 'replace'` together → `-32003 props_invalid` (discriminated union).

### Concurrency

Concurrent `update_component` calls on the same `componentId` are serialized by a per-component lock (F29). Two racing calls are applied in arrival order — never torn, never interleaved.

## `subscribe_to_events`

`Source: .vaahagents/requirements/specs/features/feature-018-subscribe-to-events-tool.md` (F18)

Returns a `subscriptionId` and starts forwarding matching `COMPONENT_EVENT` frames back to the agent. Subscriptions are scoped to one component and an optional event-name filter.

### Input schema

```ts
{
  componentId: string;
  events?: string[];     // omit = subscribe to all events for the component
}
```

### Output schema

```ts
{
  subscriptionId: string; // "sub-9c2a"
  componentId: string;
  events: string[];       // resolved filter (or "*" if all)
}
```

### Server push (subsequent)

```json
{
  "v": 1,
  "channel": "__mcp__",
  "type": "EVENT",
  "payload": {
    "subscriptionId": "sub-9c2a",
    "componentId": "dt-sess9f8e-01HK9X",
    "event": "row_selected",
    "data": { "rowId": "1" }
  },
  "seq": 14
}
```

### Example

::code-group
```json [Request]
{ "name": "subscribe_to_events", "arguments": { "componentId": "dt-sess9f8e-01HK9X", "events": ["row_selected"] } }
```

```json [Response]
{ "subscriptionId": "sub-9c2a", "componentId": "dt-sess9f8e-01HK9X", "events": ["row_selected"] }
```
::

### Failure modes

- `-32005 event_unknown` — `events` filter names an event the component doesn't emit.
- `-32001 component_not_found` — `componentId` is not currently mounted.
- `-32006 subscription_not_found` — `unsubscribe` references a missing `subscriptionId`.

### Auto-cleanup

When a component unmounts (`unmount_component` or session teardown), every subscription against it auto-closes with `subscription.closed`. The agent never needs to clean up explicitly.

## Tool wiring cheatsheet

| Tool | Reads | Writes | Emits (wire) |
|------|-------|--------|--------------|
| `find_ui_component` | registry | — | none (RPC only) |
| `render_component` | registry, propsSchema | componentStore | `STATE_SNAPSHOT` + `COMPONENT_MOUNTED` |
| `update_component` | current state | componentStore | `STATE_DELTA` or `STATE_SNAPSHOT` |
| `subscribe_to_events` | subscriptionStore | subscriptionStore | filtered `COMPONENT_EVENT` pushes |

Every tool call also emits the AG-UI run lifecycle frames (`RUN_STARTED` → `TOOL_CALL_STARTED` → `TOOL_CALL_ARGS` → `TOOL_CALL_RESULT` → `RUN_FINISHED`) on the `__mcp__` channel. AG-UI-native consumers (CopilotKit, LangGraph) consume those frames as-is — no GenicUI-specific adaptation needed.
