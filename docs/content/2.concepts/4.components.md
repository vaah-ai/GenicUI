Every GenicUI component is a Web Component — a `customElements.define`-registered class extending `GenicElement` from `@genicui/runtime`. The runtime engine mounts it inside a closed Shadow DOM, applies patches to its `props` attribute, and tears it down when the server emits `channel.closed`. This page is the lifecycle reference.

## Web Component lifecycle

A GenicUI component follows the standard custom-element lifecycle, but the runtime drives each callback. The five phases below describe a single mount-and-patch flow.

::steps
### `constructor()`

Runs once when the element is created. The runtime constructs the element with `new MyEl()`, captures any synchronous setup, and attaches a closed Shadow Root via `attachShadow({ mode: 'closed' })`. After construction, no further setup runs — the element is inert until it's added to the DOM.

### `connectedCallback()`

Fires when the element is appended to a parent. The runtime calls this when a `STATE_SNAPSHOT` arrives for a fresh `componentId`. Inside, the base class reads the `props` attribute, applies the initial state to the Shadow DOM, and emits a `client.hello` frame back to the server to establish the reverse subscription.

### `attributeChangedCallback()`

Fires when any attribute in `observedAttributes` changes. The base class observes `props`, `component-id`, and `surface` — when `props` changes (because a `STATE_DELTA` arrived), the runtime diffs the JSON-serialized prop tree and calls the element's `onPatch()` method with the patch list. The element re-renders only the changed sub-tree.

### `disconnectedCallback()`

Fires when the element is removed. The runtime calls this when `channel.closed` arrives. The base class tears down internal listeners, emits `channel.closed` to confirm teardown, and disposes the channel handler.

### `adoptedCallback()`

Runs when the element is moved to a new document. GenicUI does not currently support cross-document adoption — the runtime ignores this callback. Components moved between roots within the same document retain their channel.
::

## Why closed Shadow DOM

GenicUI uses `attachShadow({ mode: 'closed' })` for every component. The trade-off is intentional:

- **No global CSS bleed.** Page-level styles cannot pierce the Shadow boundary, and component styles cannot leak out. PrimeVue's scoped CSS, Mantine's design tokens, and shadcn's Tailwind reset all stay where they belong.
- **No accidental introspection.** Page scripts cannot reach into the shadow root via `element.shadowRoot`. The runtime is the only path in, via the closed reference held inside the base class.
- **Composable with any framework.** PrimeVue 4's PassThrough API hooks mount points without DOM probing; Vue, React, and Solid components can sit inside without prop-drilling through the boundary.

::callout{type="warning"}
The `mode: 'closed'` choice is locked in F21 and codified in the implementation. Components that try to re-open the Shadow Root break the contract — agents and registries cannot assume any element exposes `shadowRoot`.
::

## The `GenicElement` base class

`Source: packages/client/src/web-component/genetic-element.ts` exports the base class. Every registry component extends it.

```ts
import { GenicElement } from '@genicui/runtime';

class DataTableElement extends GenicElement {
  static get observedAttributes() {
    return ['props', 'component-id', 'surface'];
  }

  connectedCallback() {
    super.connectedCallback();   // attaches closed shadow, parses props
    this.update(this.props);    // initial render
  }

  onPatch(patches: JsonPatchOp[]) {
    // Diff-paint: only re-render the changed sub-tree.
    for (const op of patches) this.applyOp(op);
  }

  onEvent(name: string, detail: unknown) {
    // Bubble composed events up to the runtime.
    this.dispatchEvent(new CustomEvent(name, { detail, bubbles: true, composed: true }));
  }
}

customElements.define('genic-data-table', DataTableElement);
```

The base class provides:

- **Reactive props** — `get props()` returns the JSON-parsed `props` attribute and triggers `onPatch()` whenever the attribute mutates.
- **Lifecycle hooks** — `connectedCallback`, `disconnectedCallback`, `attributeChangedCallback` already wired; subclasses override `onPatch` and `onEvent`.
- **Event bubbling** — any `composed: true` CustomEvent dispatched inside the Shadow DOM reaches the runtime listener on the document.

## Observed attributes

Every GenicUI element observes three attributes:

| Attribute | Type | Purpose |
|-----------|------|---------|
| `props` | JSON string | Serialized component props. Updates drive re-render. |
| `component-id` | string | The channel key. Set once at mount; never mutated. |
| `surface` | string | Mount surface (`default`, `chat-panel`, etc.). Set once at mount. |

Only `props` mutates over a component's lifetime. The runtime encodes each `STATE_DELTA` as a `props` attribute mutation with a custom event to trigger `attributeChangedCallback`. The base class's `get props()` re-parses the JSON and `onPatch()` receives the diff.

## The runtime engine

`Source: packages/client/src/index.ts` exports `createRuntime`. The runtime is a module-isolated sub-module (F29-AC4) that mounts, patches, and tears down components.

```ts
import { createRuntime } from '@genicui/client';

const rt = createRuntime({
  socket,         // GenicClient WebSocket
  registry,       // component registry (loaded by Vite plugin)
  sessionStore,   // SessionStore for last-event-id replay
});

rt.onMessage(frame);   // routes frame → mount / patch / unmount / event
```

The runtime's job:

1. Receive a frame from `GenicClient`.
2. Switch on `frame.type`:
   - `STATE_SNAPSHOT` → resolve the registry entry, instantiate the element, append to the DOM, dispatch a synthetic attribute change.
   - `STATE_DELTA` → resolve the patch list against the live element, set the `props` attribute.
   - `COMPONENT_EVENT` (from the server) → forward to the agent via `__mcp__`.
   - `channel.closed` → remove the element from the DOM, dispose handlers.
3. Emit outbound frames for `client.hello` and `COMPONENT_EVENT` back to the server.

The runtime is **module-isolated** — it sets no globals on `window`. Test it with `import { createRuntime } from '@genicui/client'` and you get a fresh instance per call.

## Mount and patch timing budgets

The runtime enforces two timing budgets. Failing either closes the channel with WS code 1011 (internal error):

| Frame | Budget | Source |
|-------|--------|--------|
| `STATE_SNAPSHOT` → DOM mount | ≤ 50 ms | F29-AC1 |
| `STATE_DELTA` → DOM patch | ≤ 10 ms | F29-AC2 |

These budgets assume a typical PrimeVue DataTable mount. Heavy frameworks or large initial states may exceed them — registries with large prop payloads should consider lazy loading or `STATE_SNAPSHOT` chunking (Phase 2).

## Mount and patch flow

```text
              ┌────────────────────────┐
              │ GenicClient.onMessage  │
              └──────────┬─────────────┘
                         ▼
              ┌────────────────────────┐
              │ runtime.onMessage      │
              └──────────┬─────────────┘
                         ▼
            ┌────────────────────────────┐
            │ switch (frame.type)         │
            └──────────┬──────────────────┘
                       │
       ┌───────────────┼────────────────┐
       ▼               ▼                ▼
 STATE_SNAPSHOT   STATE_DELTA     channel.closed
       │               │                │
       ▼               ▼                ▼
  new MyEl()    setAttribute('props',  parent.removeChild(el)
  attachShadow  JSON.stringify(state))    dispose
  append to DOM attributeChangedCallback
  setAttribute  → onPatch(patches)
  → update()    → applyOp per op
```

## PassThrough API (PrimeVue 4)

The PrimeVue 4 registry uses PrimeVue's PassThrough API to wire event handlers and props without DOM probing. Each GenicUI component extends the base `GenicElement`, then in its `onPatch` it forwards props to the underlying PrimeVue component instance through a `pt` (pass-through) object:

```ts
// Source: registries/primevue/src/data-table.ts
import PrimeVueDataTable from 'primevue/datatable';

onPatch(patches: JsonPatchOp[]) {
  for (const op of patches) {
    const [key, value] = applyOp(this.props, op);
    this.primevueRef.setProp(key, value);   // ← PassThrough
  }
  this.primevueRef.emit('patch-applied');
}
```

The runtime never touches PrimeVue's internals — PrimeVue receives a `MutationObserver`-driven prop change and re-renders itself. The 8-prop `gv-data-table` API wraps PrimeVue's 30+ props down to the smallest set agents need.

## Unmount cleanup

When the agent calls `unmount_component` (internal tool, F19) or the session tears down, the runtime:

1. Receives `channel.closed` on the component's channel.
2. Calls `parent.removeChild(el)` — fires `disconnectedCallback`.
3. The base class removes event listeners and clears the `props` cache.
4. The runtime removes the channel handler from `GenicClient`'s subscription map.
5. `subscription.closed` fires for every active `subscribe_to_events` against the component.

The component's Web Component instance is garbage-collected once no JS references hold it. No state survives — every mount is fresh.
