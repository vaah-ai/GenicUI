A single WebSocket carries up to 256 channels — one per mounted component plus three reserved system channels. Each channel has its own monotonic `seq` counter, its own subscriber list, and its own replay buffer. This page describes how frames route, how out-of-order delivery is reconciled, and how the server deduplicates retries.

## Channel model

Every GenicUI WebSocket carries a fixed channel set:

| Channel | Purpose | Who emits |
|---------|---------|-----------|
| `__session__` | Session handshake + heartbeats | server only |
| `__mcp__` | Tool calls, tool results, JSON-RPC envelopes | server + agent |
| `__agent__` | Agent-to-server responses (rare; mostly server-mediated) | server mediated |
| `<componentId>` | One per mounted component | server + client |

`<componentId>` follows the form `<short>-<sessionSuffix>-<ulid>` — for example, `dt-sess9f8e-01HK9X`. The prefix encodes the registry component (`dt` = DataTable), the session suffix scopes the mount, and the ULID guarantees uniqueness across the cluster.

::callout{type="warning"}
The three reserved channels (`__session__`, `__mcp__`, `__agent__`) are checked at mount time. Reusing one as a component channel returns `-32008 surface_unavailable` and closes the allocation.
::

The 256-channel cap is enforced server-side. Opening the 257th channel returns `-32001 component_not_found` and emits `channel.closed` for the would-be channel — the existing 256 channels stay open.

## Frame envelope schema

`Source: packages/core/src/index.ts` exports the canonical `FrameEnvelopeSchema` (TypeBox-derived JSON Schema 2020-12):

```ts
import { Type, type Static } from '@sinclair/typebox';

export const FrameEnvelopeSchema = Type.Object({
  v: Type.Literal(1),
  channel: Type.String({ minLength: 1, maxLength: 128, pattern: '^[\\x21-\\x7E]+$' }),
  type: Type.String({ minLength: 1, maxLength: 64 }),
  payload: Type.Unknown(),
  seq: Type.Integer({ minimum: 0, maximum: Number.MAX_SAFE_INTEGER }),
});

export type FrameEnvelope = Static<typeof FrameEnvelopeSchema>;
```

Key invariants:

- `v` is locked to `1` until a future protocol version ships.
- `channel` rejects any control character — no newlines, no NULs.
- `payload` is `unknown` because the per-type payload schema lives in the event catalog.
- `seq` is uint64; in JavaScript that's bounded to `Number.MAX_SAFE_INTEGER` (2^53 − 1) since sequences above that risk float drift.

## Sequence ordering

Every channel carries a monotonic `seq` counter that the server increments per emit. The counter resets to `1` on mount and runs until `channel.closed`.

```text
  seq 1   STATE_SNAPSHOT     { state: { rows: [] } }
  seq 2   COMPONENT_MOUNTED  { schema, initialState }
  seq 3   client.hello       (from client → server)
  seq 4   STATE_DELTA        { patch: [{ op: 'add', path: '/rows/-', value: {...} }] }
  seq 5   COMPONENT_EVENT    { action: 'row_selected', detail: { rowId: '2' } }
  seq 6   channel.closed     { reason: 'agent_unmount' }
```

### Out-of-order buffering

Frames may arrive out of order — TCP can reorder, and intermediate proxies may delay a `seq 5` behind a `seq 7`. The client buffers per-channel until `seq` is contiguous:

```text
  received seqs: 3, 4, 7, 5, 6
  ─► contiguous from 3 → apply 3, 4
  ─► 5 and 6 held; 7 buffered
  ─► on arrival of 5: apply 5, 6
  ─► on arrival of 6: apply 6, then 7
  ─► invariant: application is always in seq order, never arrival order
```

The buffer is bounded per channel — 500 frames in F33's session buffer. Exceeding the bound closes the socket with WS code 1013 (try again later) and forces the client to reconnect with `Last-Event-ID`.

### Hard rule: STATE_DELTA before COMPONENT_EVENT

When state and an event happen in the same logical step, the server **always** emits `STATE_DELTA` before any `COMPONENT_EVENT` that observes that state. The client guarantees causal consistency this way — by the time the event reaches the agent, the row the agent clicked is already updated.

## Idempotency keys

`render_component` and `update_component` accept an optional `clientRequestId` (UUID v4) that the server caches for 24 hours. Retries with the same `id` return the original response without re-executing the tool:

```text
Agent: render_component { name: "DataTable", props: {...}, clientRequestId: "r-1" }
Server: { componentId: "dt-...", ... }    ← 200 OK, cached

Agent: render_component { name: "DataTable", props: {...}, clientRequestId: "r-1" }   ← retry
Server: { componentId: "dt-...", ... }    ← SAME response, no re-mount
```

The cache key is `(apiKey, clientRequestId)` — one agent's idempotency namespace never collides with another's. The 24h TTL is enforced by an LRU; old keys are evicted silently.

::callout{type="info"}
Idempotency is the primary defense against the Claude Code MCP retry loop. When the network hiccups mid-render, the wrapper retries the same `render_component` with the same `clientRequestId`. Without idempotency, a retry would allocate a second `componentId` and double-mount.
::

## Channel lifecycle

```text
  ┌─────────────┐  render_component  ┌─────────────┐
  │ (no channel)│ ─────────────────► │  reserved   │
  └─────────────┘                    └──────┬──────┘
                                             │ STATE_SNAPSHOT + COMPONENT_MOUNTED
                                             ▼
                                       ┌─────────────┐
                                       │   mounted   │◄──── client.hello
                                       └──────┬──────┘
                                              │
                          ┌───────────────────┼─────────────────────┐
                          ▼                   ▼                     ▼
                  ┌──────────────┐    ┌──────────────┐       ┌──────────────┐
                  │ update_comp  │    │ subscribe_to │       │ unmount_comp │
                  │ → STATE_DELTA│    │   _events    │       │ → close      │
                  └──────────────┘    └──────────────┘       └──────┬───────┘
                          │                   │                     │
                          └───────────────────┴─────────────────────┘
                                              ▼
                                       ┌─────────────┐
                                       │  closing    │
                                       └──────┬──────┘
                                              │ channel.closed
                                              ▼
                                       (channel gone)
```

The closing state is terminal — a closed channel cannot be reopened. To re-mount, the agent calls `render_component` again and gets a fresh `componentId`.

## Validation at the wire

Frames failing validation close the socket with WS code 1003 (unsupported data). The check order:

1. Single-line JSON parses.
2. `v === 1`.
3. `channel` matches the allowed pattern.
4. `type` is in the AG-UI/GenicUI event catalog.
5. `payload` conforms to the event's schema.
6. `seq` is a non-negative integer.

A failure on any step closes with `1003`. There is no half-open state — clients either see the full frame or see the socket die.
